## Environment gotchas (IMPORTANT for future runs)
- An HTTP proxy is set in the shell env (`http_proxy=http://127.0.0.1:62360`) — plain `curl` to
  `127.0.0.1` returns **502**. Use `curl --noproxy '*'` and hit **`localhost`**, not `127.0.0.1`.
- Vite binds to IPv6 `[::1]` only → must browse `http://localhost:5180/`, not `127.0.0.1:5180`.
- `npm install` fails with esbuild `EBUSY` on Windows (managed node). Fix used:
  `npm install --ignore-scripts --no-audit --no-fund` (pulled `@esbuild/win32-x64`,
  `@rollup/rollup-win32-x64-msvc`). See the `vite-windows-deps` skill.
- `vite build` may hit the sandbox safe-delete guard on `emptyOutDir` — if so set
  `build.emptyOutDir:false` + a non-recursive `clean-dist` prebuild (per skill).

## Key architecture facts
- Backend owns risk score/decision/state; frontend is a client only (`src/api.ts` is the only fetch layer).
- Chain: Risk Engine (weighted, explainable, floors+suppression) → Policy Engine (deterministic hard
  rules; regulatory HOLD wins; CRITICAL→ESCALATE/BLOCK) → MockBankAdapter.
- Demo auth = `X-User-Id` header resolved server-side to a DB role (never trust client role).
- Identity proof enforced: `POST /{id}/identity` issues deterministic demo OTP `(id*7919)%1e6`;
  `/identity/confirm` must pass before `/verify` (else 409) and before authorize.
- Purposes allowed by backend: Debt repayment | Family support | Business payment | Savings | Other
  (frontend `PURPOSES` matches). Scenario A demo beneficiary = "John Doe".
